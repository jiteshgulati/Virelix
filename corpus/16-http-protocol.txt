The Hypertext Transfer Protocol is the foundation of data exchange on the web. It follows a request-response model: a client sends a request to a server, and the server returns a response.

A request contains a method, a path, headers and an optional body. GET retrieves a resource and should not change server state. POST submits data, PUT replaces a resource, PATCH modifies part of it and DELETE removes it. Methods such as GET, PUT and DELETE are idempotent, meaning repeating the request has the same effect as sending it once.

Responses include a status code. Codes in the 200 range indicate success, 300 codes indicate redirection, 400 codes indicate client errors such as 404 Not Found or 403 Forbidden, and 500 codes indicate server errors. Headers carry metadata such as content type, caching rules and cookies.

HTTP is stateless: each request is independent. Applications build sessions on top of it using cookies, small values the server asks the browser to store and send back with later requests. Cookie attributes control security. HttpOnly prevents JavaScript from reading a cookie, Secure restricts it to encrypted connections and SameSite limits cross-site sending, which helps prevent cross-site request forgery.

HTTP/1.1 introduced persistent connections. HTTP/2 multiplexes many requests over one connection with binary framing, and HTTP/3 runs over QUIC on top of UDP to reduce connection setup latency and head-of-line blocking.
